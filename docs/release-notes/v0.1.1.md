# ReaPack Porter v0.1.1

Compatibility hotfix for existing ReaPack configuration files using legacy Windows text encoding.

## Fixed

- v0.1.0 could fail when reading some existing Windows `reapack.ini` files containing Windows-1252 characters such as `ü`.
- v0.1.1 supports those files while preserving their encoding during import.
- UTF-8 and UTF-8 BOM configurations remain supported.
- Existing backup and atomic-write protections remain in place.

## Downloads

- Linux x86_64: `ReaPack-Porter-0.1.1-linux-x86_64.tar.gz`
- Windows x86_64: `ReaPack-Porter-0.1.1-windows-x86_64.zip`
- macOS Intel x86_64: `ReaPack-Porter-0.1.1-macos-x86_64.zip`
- macOS Apple Silicon arm64: `ReaPack-Porter-0.1.1-macos-arm64.zip`

## Important

- Close REAPER completely before importing.
- Export is safe while REAPER is running.
- Windows and macOS builds are unsigned.
- macOS builds are not notarized.
- Verify the SHA256 checksum after downloading.

## After Import

Start REAPER and run:

```text
Extensions > ReaPack > Synchronize packages
```

## Legacy Lua Version

The original `reapack_porter.lua` remains available in the repository.
